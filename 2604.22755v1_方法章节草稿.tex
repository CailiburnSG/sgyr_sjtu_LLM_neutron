\section{方法}
\subsection{系统架构：事件--证据--行动的异常预检管线}

本研究使用事件--证据--行动管线，将原始中子电流 CSV 数据转化为可审查的人工核查建议。该管线包含三个阶段：（1）时序事件解析与事件卡构建；（2）人工证据卡组织与候选证据获取；（3）证据条件下的受限行动选择。在阶段 1，原始中子电流记录被确定性地解析为原子事件、单通道事件卡和聚合事件组合。在阶段 2，既定人工证据卡库保留证据文本、来源、章节或行号、主题标签及统一适用性标签；系统根据实验配置使用传统检索方法或 LLM 获取候选证据。在阶段 3，当前案例的事件组合、候选证据与固定检查建议定义共同构成推理上下文，语言模型据此从阶段 2 的候选证据中选择一项固定检查建议。

\textbf{阶段 1：时序事件解析与事件卡构建。}
令
\begin{equation}
\mathcal{S}=\{s_1,s_2,\ldots,s_N\}
\label{eq:input-records}
\end{equation}
表示输入的中子电流 CSV 记录集合，其中每条记录包含时间、通道和对应的电流观测值。系统对每个通道的时序记录采用基于零值段判别、滚动中位数与中位数绝对偏差（MAD）阈值检测的确定性分析规则，识别具有预定义模式的局部异常，并将其表示为原子事件：
\begin{equation}
\mathcal{E}=\{e_i=f_{\mathrm{event}}(s_i)\mid s_i\in\mathcal{S}\}.
\label{eq:atomic-events}
\end{equation}
原子事件保留其发生时间、所属通道、异常模式及相关数值摘要。随后，系统将同一通道内具有时间关联的原子事件组织为单通道事件卡：
\begin{equation}
c^{\mathrm{single}}_j=f_{\mathrm{single}}(\mathcal{E}_j),
\label{eq:single-channel-cards}
\end{equation}
并进一步将跨通道或相邻时间段内相关的单通道事件卡组合为聚合事件组合：
\begin{equation}
x_l=f_{\mathrm{group}}\bigl(\{c^{\mathrm{single}}_j\}\bigr).
\label{eq:event-groups}
\end{equation}

原子事件、单通道事件卡与聚合事件组合均作为独立但相互关联的对象保存。借助共享的时间范围、通道标识和事件关系，该表示既保留原始异常的可回溯性，也为后续证据获取提供统一的文本化任务输入。

\textbf{阶段 2：人工证据卡组织与候选证据获取。}
令
\begin{equation}
\mathcal{Y}=\{y_1,y_2,\ldots,y_M\}
\label{eq:evidence-library}
\end{equation}
表示人工整理的证据卡库；本研究中 \(M=300\)。每张证据卡 \(y_j\) 包含证据文本、来源信息、章节或行号、主题标签和统一适用性标签。与自动文档分块不同，证据卡是既定的人工证据单元，不在实验过程中按段落重新切分。对于采用 BM25 的 B0 和 B1 配置，系统将事件组合 \(x\) 转换为检索查询 \(q(x)\)，并计算其与各证据卡之间的词汇相关性：
\begin{equation}
r_j=\mathrm{BM25}\bigl(q(x),y_j\bigr).
\label{eq:bm25-score}
\end{equation}
检索器据此返回得分最高的 Top-K 候选证据集合：
\begin{equation}
\mathcal{Y}_K(x)=\mathrm{TopK}_{y_j\in\mathcal{Y}}\, r_j.
\label{eq:bm25-topk}
\end{equation}
在 B0 中，该候选集合进一步依据证据卡的适用性标签进行机械投票；在 B1 中，同一候选集合被提供给 LLM 进行行动选择。对于 B2，系统不使用预先固定的 BM25 候选包，而是向 LLM 提供完整证据库 \(\mathcal{Y}\)，由其针对当前事件组合独立选择指定数量的候选证据：
\begin{equation}
\mathcal{Y}_K(x)=f_{\mathrm{select}}\bigl(x,\mathcal{Y},K\bigr).
\label{eq:llm-select-topk}
\end{equation}
因此，B1 用于考察固定检索候选条件下的证据--行动推理，B2 则同时考察全库证据选择与行动选择的联合表现。

\textbf{阶段 3：证据条件下的受限行动选择。}
在阶段 3，当前案例的事件组合 \(x\)、候选证据集合 \(\mathcal{Y}_K(x)\)、固定检查建议集合 \(\mathcal{A}\) 以及系统约束提示 \(P_{\mathrm{sys}}\) 共同构成推理上下文，其中
\begin{equation}
\mathcal{A}=\{\mathrm{A1},\mathrm{A2},\mathrm{A3},\mathrm{A4}\}.
\label{eq:action-space}
\end{equation}
语言模型据此根据候选证据 \(\mathcal{Y}_K(x)\) 从 \(\mathcal{A}\) 中选择一项固定检查建议。四项行动分别对应现场操作或校准核查、跨通道相似异常比较、记录处理与时间戳核查，以及信号传输路径核查。语言模型在可选的固定示例上下文 \(P_{\mathrm{ex}}\) 条件下输出一项检查建议：
\begin{equation}
\hat{z}=f_{\mathrm{LLM}}\bigl(x,\mathcal{Y}_K(x),\mathcal{A},P_{\mathrm{sys}},P_{\mathrm{ex}}\bigr),
\quad \hat{z}\in\mathcal{A}.
\label{eq:action-selection}
\end{equation}
在 B2 中，证据选择和行动选择是针对每个案例独立执行的两个阶段；行动选择阶段只使用该次证据选择所产生的候选证据，不复用其他案例、其他配置或其他运行中的选择结果。输出以 JSON 形式返回，并接受格式与内容合同验证：
\begin{equation}
V(\hat{z})=
\begin{cases}
1, & \text{若输出合法且仅包含一项 } \mathcal{A} \text{ 中的行动；}\\
0, & \text{否则。}
\end{cases}
\label{eq:action-contract}
\end{equation}

\subsection{定量评价}

现有检索增强与异常分析评价通常强调候选文档排序、字符串匹配或最终分类准确率，却较少同时检验候选证据是否与人工检查意图一致、证据是否足以支持相应的核查建议，以及系统输出是否遵守预先定义的行动边界。常用的 Precision@K、Recall@K 和分类 Accuracy 等指标对于通用检索或分类任务具有参考价值，却不能直接评价不同证据卡在语义上是否承担相同的核查支持作用，也不能区分“未获取合适证据”与“已获取合适证据但行动选择错误”这两类失效模式。

因此，本文引入一组面向事件--证据--行动工作流的评价指标，用于刻画候选证据质量、证据与行动之间的一致性、最终行动选择正确性以及输出格式合规性。正式评价集由冻结的 \(N=60\) 个金标准案例构成：
\begin{equation}
\mathcal{G}_{\mathrm{eval}}=
\{(x_i,\mathcal{Y}^{*}_i,\mathcal{U}^{*}_i,a^{*}_i)\}_{i=1}^{N}.
\label{eq:evaluation-set}
\end{equation}

其中，\(x_i\) 为事件组合，\(\mathcal{Y}^{*}_i\) 为人工整理的金标准证据卡集合，\(a^{*}_i\) 为固定人工检查建议。每个金标准案例包含一个由 1--4 个事件原子构成的事件组合、3 张共同支持同一检查意图的证据卡，以及 A1--A4 中的一项固定检查建议。

证据卡与语义单元之间通过既定人工映射关联。令 \(m(y)\) 表示证据卡 \(y\) 对应的一个或多个语义单元，则案例 \(i\) 的金标准语义集合为
\begin{equation}
\mathcal{U}^{*}_i=
\bigcup_{y\in\mathcal{Y}^{*}_i}m(y).
\label{eq:gold-semantic-units}
\end{equation}
因此，3 张金标准证据卡虽然共同支持同一行动 \(a_i^{*}\)，但可提供相互补充的技术论据，并对应多个语义单元。语义单元用于描述证据所承担的支持作用；其与行动的对应关系由当前金标准案例中的“语义单元--固定检查建议”配对确定，而不要求每个语义单元在所有事件情境下唯一决定一项行动。

对于系统返回的候选证据集合 \(\hat{\mathcal{Y}}_{i,K}\)，其语义集合定义为
\begin{equation}
\hat{\mathcal{U}}_{i,K}=
\bigcup_{y\in\hat{\mathcal{Y}}_{i,K}}m(y).
\label{eq:predicted-semantic-units}
\end{equation}
金标准证据集合并不假定穷尽证据库中所有可能有效的支持来源；它提供评价与人工核验的统一锚点。金标准案例标识仅用于离线评价，且不传入任何模型提示词。以下指标逐案例计算后，再在冻结评估集上汇总。

为简化表述，对任意预测集合 \(A\) 与金标准集合 \(B\)，定义
\begin{equation}
\mathrm{Prec}(A,B)=\frac{|A\cap B|}{\max(|A|,1)},
\qquad
\mathrm{Rec}(A,B)=\frac{|A\cap B|}{|B|},
\label{eq:set-precision-recall}
\end{equation}
\begin{equation}
\mathrm{F1}(A,B)=
\frac{2\,\mathrm{Prec}(A,B)\,\mathrm{Rec}(A,B)}
{\mathrm{Prec}(A,B)+\mathrm{Rec}(A,B)},
\label{eq:set-f1}
\end{equation}
当式~\eqref{eq:set-f1} 的分母为零时，\(\mathrm{F1}(A,B)\) 定义为零。

\textbf{1. 语义证据精确度、召回率与 F1 值。}
候选证据质量不以证据卡 ID 的逐卡一致作为唯一标准；来自不同来源的证据卡只要映射到相同语义单元，即可构成语义上的可接受替代。语义证据精确度、召回率与 F1 值分别定义为
\begin{equation}
\mathrm{SP@K}_i=\mathrm{Prec}(\hat{\mathcal{U}}_{i,K},\mathcal{U}^{*}_i),
\qquad
\mathrm{SR@K}_i=\mathrm{Rec}(\hat{\mathcal{U}}_{i,K},\mathcal{U}^{*}_i),
\label{eq:semantic-precision-recall}
\end{equation}
\begin{equation}
\mathrm{SF1@K}_i=\mathrm{F1}(\hat{\mathcal{U}}_{i,K},\mathcal{U}^{*}_i).
\label{eq:semantic-f1}
\end{equation}
SP@K 衡量候选语义的相关性，即候选包中有多少语义与当前金标准论据一致；SR@K 衡量论据覆盖完整度，即金标准中的互补语义有多少被候选包恢复；SF1@K 则综合两者。

\textbf{2. 语义候选覆盖率。}
语义候选覆盖率（Semantic Candidate Coverage@K，SCC@K）衡量每个案例的候选证据包是否至少包含一项与金标准一致的证据语义：
\begin{equation}
\mathrm{SCC@K}_i=
\begin{cases}
1, & \text{若 } \hat{\mathcal{U}}_{i,K}\cap\mathcal{U}^{*}_i\neq\varnothing;\\
0, & \text{否则。}
\end{cases}
\label{eq:semantic-coverage}
\end{equation}
该指标不同于 SR@K：SR@K 关注金标准语义被覆盖的程度，而 SCC@K 仅回答候选包是否为后续行动选择提供了至少一项可接受的证据依据。其系统级均值表示在全部案例中，系统成功向后续阶段提供可接受候选证据的比例。

\textbf{3. 语义--行动对 F1 值。}
仅有语义正确的候选证据并不保证最终检查建议正确；同样，偶然预测正确的行动也不表示其具有与该行动一致的证据依据。为同时评价两者，本文将每个候选语义单元与该案例的行动标签组成语义--行动对：
\begin{equation}
\hat{\mathcal{P}}_{i,K}=
\{(u,\hat{a}_i)\mid u\in\hat{\mathcal{U}}_{i,K}\},
\qquad
\mathcal{P}^{*}_i=
\{(u,a^{*}_i)\mid u\in\mathcal{U}^{*}_i\}.
\label{eq:semantic-action-pairs}
\end{equation}
语义--行动对 F1 值定义为
\begin{equation}
\mathrm{SCA\mbox{-}F1@K}_i=
\mathrm{F1}(\hat{\mathcal{P}}_{i,K},\mathcal{P}^{*}_i).
\label{eq:semantic-action-pair-f1}
\end{equation}
该指标要求语义单元与行动标签同时匹配。若 \(\hat{a}_i\neq a_i^{*}\)，预测对与金标准对不存在交集，SCA-F1@K 为零；若行动正确，则该指标进一步根据候选证据对金标准语义论据集合的覆盖程度给分。因此，它将“行动是否正确”与“该行动是否由一致且相对完整的证据语义支撑”结合起来。

\textbf{4. 最终行动准确率与宏平均 F1 值。}
最终行动准确率（Action Accuracy，Acc）衡量系统是否预测出与金标准一致的固定人工检查建议：
\begin{equation}
\mathrm{Acc}=
\frac{1}{N}\sum_{i=1}^{N}\mathbb{I}(\hat{a}_i=a^{*}_i).
\label{eq:action-accuracy}
\end{equation}
由于四类检查建议在评估集中可能并非完全均衡，本文同时报告宏平均 F1 值（Macro-F1，MF1）：
\begin{equation}
\mathrm{MF1}=
\frac{1}{|\mathcal{A}|}\sum_{a\in\mathcal{A}}\mathrm{F1}_{\mathrm{class}}(a),
\qquad
\mathcal{A}=\{\mathrm{A1},\mathrm{A2},\mathrm{A3},\mathrm{A4}\}.
\label{eq:macro-f1}
\end{equation}
其中，\(\mathrm{F1}_{\mathrm{class}}(a)\) 为将行动 \(a\) 视为正类时得到的类别 F1 值。Macro-F1 对四类行动给予相同权重，因此能够避免高频行动类别主导总体结果。

\textbf{5. JSON 合法率与输出合同合规率。}
除证据与行动质量外，系统还必须满足可机器读取和任务边界要求。JSON 合法率（JSON Validity Rate，JVR）衡量模型输出能否被正确解析为预期 JSON 结构：
\begin{equation}
\mathrm{JVR}=
\frac{1}{N}\sum_{i=1}^{N}\mathbb{I}(\mathrm{parse}(\hat{o}_i)=1),
\label{eq:json-validity}
\end{equation}
其中 \(\hat{o}_i\) 为案例 \(i\) 的原始模型输出。输出合同合规率（Output Contract Compliance Rate，OCCR）进一步衡量解析后的输出是否满足当前阶段的全部约束：
\begin{equation}
\mathrm{OCCR}=
\frac{1}{N}\sum_{i=1}^{N}\mathbb{I}(\hat{o}_i\text{ satisfies contract}).
\label{eq:contract-compliance}
\end{equation}
对于行动选择阶段，合同要求输出恰好一项 A1--A4 中的检查建议；对于 B2 证据选择阶段，合同还要求输出恰好 \(K\) 张来自既定证据库、且互不重复的候选证据。JSON 合法率只检验格式可解析性，而合同合规率检验输出是否同时满足结构、字段和值域等任务约束。

\textbf{6. 平均指标。}
系统级表现报告为冻结 60 例评估集上各逐案例指标的均值：
\begin{equation}
\overline{M}=\frac{1}{N}\sum_{i=1}^{N}M_i.
\label{eq:mean-metric}
\end{equation}
其中，SCC@K 的均值表示至少获得一项可接受候选证据的案例比例；Acc 表示最终检查建议正确的案例比例；JVR 和 OCCR 分别表示输出在语法层面与任务合同层面的合规比例。这些指标为比较 BM25 与适用性标签机械投票基线、固定 BM25 候选包上的 LLM 行动选择，以及全证据库 LLM 证据选择与行动选择提供了紧凑框架。它们不将系统表现压缩为单一分数，而是分别衡量：（i）候选证据的语义相关性与覆盖完整度；（ii）证据语义与检查建议的联合一致性；（iii）最终行动选择的正确性；以及（iv）输出格式和任务边界的合规性。

\subsection{系统模块}

事件--证据--行动管线以原始中子电流 CSV 的确定性事件解析和人工证据卡库为主要输入机制，并通过表~\ref{tab:modules} 概括的功能模块完成候选证据获取、受限行动选择和结果验证。与由代理根据开放式用户查询在运行时任意选择工具的系统不同，本文的模块调用顺序由实验配置预先确定：B0 使用 BM25 检索与适用性标签机械投票；B1 使用 BM25 候选证据包与 LLM 行动选择；B2 则依次执行全库 LLM 证据选择与 LLM 行动选择。该设计使不同配置能够在同一事件表示、同一人工证据库和同一冻结评估集上进行可复现比较，同时保持候选证据、行动输出与评价结果之间的可追溯关系。

该框架独立于某一特定预训练模型的内部参数：模型在所有实验中保持冻结。使用远程 LLM API 时，系统会将当前实验配置所需的事件组合、候选证据或全库证据卡及提示内容提供给模型。

在方法执行层面，原始 CSV、事件卡、证据卡、金标准案例、个案 JSON/JSONL 输出及汇总量化指标均保持为彼此可关联的研究对象。对于 LLM 输出，系统分别检查 JSON 是否可解析，以及输出是否满足当前阶段的要求，例如行动选择是否只返回一项 A1--A4 行动，或证据选择是否返回指定数量且来自既定证据库的候选卡片。通过来源定位、个案记录和合同检查，系统将异常事件、证据依据和人工检查建议之间的关系保留为可逐项审查的链条。

\subsection{实验配置与基准设计}

为评价所提出的事件--证据--行动架构，本文整体评估由两部分内容组成：（i）在不同候选证据数量 \(K\) 下，对证据获取质量及其对行动选择的影响进行分析；（ii）在不同固定示例数量 \(n\) 及不同示例注入位置下，对上下文学习如何影响证据选择和行动选择进行消融分析。每个正式评估案例均依据本节定义的量化指标报告，而不被压缩为单一综合分数。

正式评估使用冻结的 60 个案例，候选证据规模取 \(K\in\{3,5,8,10\}\)。B0 作为非 LLM 基线，使用 BM25 Top-K 检索与适用性标签机械投票；B1 在与 B0 完全相同的 BM25 候选证据包上引入 LLM 行动选择；B2 则由 LLM 面向完整人工证据库独立选择候选证据，再据此由 LLM 进行行动选择。B1 和 B2 均比较零样本与不同数量固定示例下的结果。其中，B1 仅在行动选择端加入固定示例；B2 分别在证据选择端（\textit{selector}）、行动选择端（\textit{action}）和两个阶段（\textit{both}）加入固定示例。B2 的固定示例消融限定在 \(K\in\{3,5,8\}\)，因为其零样本 \(K=10\) 配置出现明显的行动输出合同不合规。所有涉及 LLM 的正式运行均采用参数冻结的 \texttt{qwen3.8-flash} 模型、温度 0 设置，并按案例串行执行。
