# V3 中文论证稿

> 状态：起草。此文件先解决“论文要说什么”，不写成英文句子的逐句底稿。

## 1. 场景

本研究面向同一核电厂采集周期内的中子电流历史档案：42 条多通道记录来自四个仪表组，每条包含时间列与 7 个中子电流通道，典型记录为约 $6\times10^5$ 个、采样间隔约为 1 s 的连续样本。

在未获得明确许可前，不披露反应堆型号、厂站身份、具体仪表系统名称或其他可识别信息。

## 2. 问题

这些记录缺少统一的样本级故障真值。要将某段波形可靠地解释为具体设备故障，需要结合运行工况、维护历史和仪表知识；仅凭 CSV 不能建立可信的监督标签库。因而，问题不是让模型从波形自动输出故障类别，而是让工程师能够在 archive 规模上审查被压缩、可追溯的信号现象及其技术证据。

## 3. 唯一中心 idea

在原始测量与工程判断之间显式建立一个 **可追溯的 measurement-to-evidence interface**。它连接两个不可混同、但各自内部完整的部分：测量侧以确定性工具将原始时序组织为可回溯的观测与结构化告警摘要；证据侧以该摘要为受控检索描述，在来源策略约束下组织技术证据和带引文的候选解释。工程师复核位于接口之外，保留最终判断责任。

该接口使原始时序不被直接提升为故障结论，也使手册片段不被误当作对未处理波形的直接解释。

## 4. 方法因果链

1. 测量侧的预先定义的确定性工具产生 spike、zero、lag、共变、极值和数据健康等观测；workspace 保存输入、参数、状态和派生产物，其中稳定字段直接构成 structured alert summary。
2. 测量侧语言模型只读取已保存的观测，将其组织为供工程师阅读的 condition report，不增加新的测量事实。
3. 证据侧以该摘要形成受控检索意图，从具有来源 metadata 的技术资料中检索可定位证据，并接受 authority policy 约束；证据侧语言模型组织候选解释和引用。物理机制与最终工程判断保留给接口外的工程师。

## 5. 本文可主张与不可主张

### 可主张

- 描述性观测可在无统一 fault ground truth 的 archive 上形成可追溯中间层。
- corpus 扩张时，semantic similarity 与指定权威来源的可见性可能背离。
- query、语言、encoder 和 chunking 的交互会影响 retrieval governance。

### 不可主张

- 自动 fault diagnosis accuracy 或 root-cause accuracy；
- `Priority@k` 等同于人类相关性或技术证据质量；
- 自动 memo 已经具有未经专家复核的工程正确性。

## 6. 待确认事实

- 反应堆类型、探测器类别和监测任务的可披露范围；
- 可参与 observation、passage、claim 和 usefulness 专家复核的领域人员；
- 是否能够获得脱敏的运行或维护背景，用于未来 mechanism-hypothesis 层。

## 7. V3 的中心问题与一句话主张

### 中心问题

在缺乏可靠故障真值的核电仪表历史档案中，如何让工程师以可追溯、受权威来源约束的方式，从海量原始时序走到可审查的候选解释，同时不把自动化系统伪装为故障诊断器？

这个问题同时解释了三类现有路径的不足：

- 不能直接做监督分类：原始 CSV 没有足以支撑统一类别标签的运行、维护和仪表上下文；
- 不能让 LLM 直接阅读波形后给出故障结论：生成内容缺少对测量现象和技术依据的受控连接；
- 不能只做文档 RAG：文档本身不能替代对未处理时序的描述与可复现观测。

### 一句话主张

本文提出一种面向无标签核仪表时序档案的、**证据约束的诊断辅助接口**。该接口不声称自动识别故障，而是将可复现的测量现象与受来源策略约束的技术证据连接起来，使工程师能够审查候选解释的测量依据与文献依据。

## 8. 论文应遵循的叙事主线

V3 不是“比较哪一种检索配置最好”的论文。它首先是一篇关于工程解释边界与可追溯接口的论文；检索实验用于证明该接口为何不能只按语义相似度治理。

建议全文按以下因果顺序推进：

1. **真实约束**：档案规模大、信号复杂，但不存在可直接用于训练和评估的统一故障真值。
2. **方法缺口**：直接分类、自由 LLM 推断和脱离时序的文档 RAG 都无法提供可信的工程解释链。
3. **接口方案**：建立连接测量侧可追溯观察与证据侧候选解释的接口，并将人工复核明确保留在接口外。
4. **分层验证**：分别核查观测是否可复现、检索是否遵从来源策略、以及陈述是否获得相应证据支持；不把这些指标混写成“诊断准确率”。
5. **工程含义**：系统让工程师更容易审查 archive 中值得关注的现象及其资料依据，而不是替代工程判断。
6. **明确边界**：只有在补充运行历史、维护记录和专家复核后，才可能进入机理假设和故障确认层。

## 9. 检索实验与 P0 的正确位置

P0 以及 query、语言、encoder 和 chunking 的实验应服务于下面的支持性论点：

> 候选解释依赖检索到的技术证据；因此，检索配置不能仅依据 cosine similarity 选择。查询形式、语言、编码器和分块策略会改变预设权威来源是否可见，来源治理必须被显式设计与评价。

因此，实验结果不应被表述为“某个 embedding 或某种 chunking 普遍最好”，而应回答：在本研究设定与来源策略下，哪些配置会改变证据的可见性、可定位性和可审查性。P0 是这一论点的证据，不是本文存在的唯一理由。

## 10. 贡献、证据与结论的对齐

| 层次 | 论文可以给出的贡献 | 需要的证据 | 不应越过的结论 |
| --- | --- | --- | --- |
| 测量观测 | 将长时序转为可复现、可回溯的 observation packet | 输入、参数、probes 和派生产物的可追溯记录 | 已确认具体设备故障 |
| 检索治理 | 将观测意图连接到有 metadata 和来源策略的技术证据 | corpus、query、ranking 与来源可见性比较 | 相似度高即代表证据质量高 |
| 候选解释 | 以引文连接观测与可能的技术解释 | passage--claim support 与引用定位 | 自动 memo 已被证明工程正确 |
| 工程价值 | 为人工复核提供更清晰的审查入口 | 领域人员对 observation、passage、claim/usefulness 的专家复核（如可获得） | 系统替代工程师决策 |

若暂时无法获得领域人员复核，V3 仍可以稳妥地定位为“框架与检索治理研究”；届时必须将候选解释的有用性和工程正确性明确列为未验证边界，而不能在摘要或结论中暗示其已被专家确认。

## 11. 篇幅约束与删减原则

### 目标

导师建议将正文控制在约 10 个版面。V3 应把这视为对论证密度的提醒，而非机械排版任务：篇幅越长，未经充分验证的细节、图表解释和可被质疑的旁支结论越多，后续维护和审稿风险也越高。

V2 的约 17 个版面和 20 张图仅作为可回溯的素材库；它们不构成 V3 必须继承的内容清单。V3 **不预设图表数量上限**：图、表和文字的取舍均由它们对中心论点的不可替代性决定，而不是由固定配额决定。

### 建议的十页信息预算

| 部分 | 建议篇幅 | 只回答的核心问题 |
| --- | ---: | --- |
| 引言 | 1.0--1.2 页 | 为什么无标签 archive 需要可追溯接口，而非直接分类或自由 LLM 推断？ |
| 场景与接口方法 | 1.5--2.0 页 | 测量、观测、证据和工程判断如何分层连接？ |
| 分层评价设计 | 1.0--1.2 页 | 为什么这些评价衡量接口与来源治理，而不是诊断准确率？ |
| 结果 | 2.5--3.0 页 | 接口产生了什么可审查 trace；为什么相似度不足以治理证据？ |
| 讨论、局限与结论 | 1.2--1.5 页 | 系统能做什么、不能做什么，以及下一步需要什么证据？ |
| 图、表、参考文献与版式余量 | 约 1.5--2.0 页 | 为读者保留理解主要证据所需的空间。 |

### 图表应承担的论证角色（不设数量上限）

V3 可能需要下列类型的图表，但是否保留、使用几张以及是否合并，应在写作和审稿式核对中逐项决定：

- **接口图**：交代 measurement-to-evidence interface 的边界、产物和工程师所在的位置。
- **代表性 trace case**：将原始信号的关键现象、observation packet、structured alert 和被引用证据连接起来。
- **来源治理结果**：说明 corpus 扩展后，语义相似度与预设权威来源可见性可能背离。
- **P0 或其他配置交互结果**：支持“无普适最优、配置影响证据可见性”的具体证据。
- **数据/评价表**：当表格确实比连续文字更清楚地表达数据边界、评价层级或协议时使用。

图表的数量不是目标。必要时可以保留超过四张图或两张表；反之，若某项信息无法支撑主张，即使版面尚有余量也不应保留。

### 删减与迁移规则

- 每一张图、表、公式和段落都必须能回答中心问题中的一个子问题；不能回答者不进入 V3 正文。
- 同类指标优先选择最能改变读者判断的呈现；只有当多个呈现分别承担不同、不可替代的论证任务时，才同时保留。
- spike、zero、lag、Pearson、极值等 probe 不是独立贡献，不分别展示为多张教学图；它们在一个代表性 trace 中作为观测证据出现即可。
- 不同时展示同一检索结论的 gradient、quadrant、trajectory、中英文重复图和多组 embedding 图；优先选择可直接支撑来源治理结论的一种压缩表达。
- 自检索、编码器横向比较、额外 chunking grid 等若不能改变中心结论，则删除；若需要可复现性，仅在补充材料或仓库保留。
- 不为展示实现完整性而在正文罗列工具、目录、运行时或参数细节；正文说明可追溯契约，精确参数进入附录/仓库。

### 每个结果的进入门槛

某项结果只有同时满足以下条件才进入 V3 正文：

1. 它直接支撑“从测量到证据的可追溯接口”或“来源治理不可由相似度替代”；
2. 它能在一个图、表或短段内被解释清楚；
3. 它不会诱导读者以为本文已完成故障诊断、根因确认或专家验证；
4. 删除它后，中心主张会明显失去证据。

不满足上述四项的内容不应勉强浓缩进正文；保留在 V2 是更安全的维护方式。

## 12. 引言的起草与正式呈现约定

### 正式稿的形式

V3 的正式 Introduction 不使用 `1.1`、`1.2` 等显式子标题。它应是一段连续推进的论证，而不是说明书式的分项介绍。当前中文 Markdown 中的子标题只服务于起草阶段：用于核查逻辑是否缺失、引用是否放在正确位置，以及详细数据是否已移至第二章；在进入 TeX 正文时应撤去这些标题并合并为自然段。

### 推荐的五段推进

1. **工程背景**：核仪表在线监测与中子电流测量为何具有工程意义。
2. **现实约束**：无标签历史档案为何不能自然转化为故障分类基准。
3. **研究缺口**：直接分类、自由 LLM 推断和脱离测量的文档 RAG 分别为何不足。
4. **本文方案**：提出 measurement-to-evidence interface，并简述其受限的信息流和工程师责任边界。
5. **贡献与边界**：说明本文实际贡献、不主张的诊断能力，以及后文章节安排。

### 信息放置规则

- 引言只保留形成问题所必需的定性场景约束，例如“多通道中子电流历史档案缺少统一样本级故障真值”。
- 记录数量、通道数、采样间隔、通道布局、时间戳处理、厂站/堆型披露策略等具体内容统一放在第二章。
- 引言的最后一段再列贡献；不在前半段抢先给出过多方法实现、实验指标或数据细节。
