# 论文讨论与决策指南

> 本文件是论文进行中的讨论记录与决策日志。它不替代投稿正文；每次讨论后，将已经确认的判断、仍需验证的问题和下一步优先级更新在这里。

## 1. 当前论文的一句话定位

面向弱标签核电中子电流数据，构建一个受约束的零先验诊断工作流：从时序数据中发现可核查现象，检索权威技术手册形成带引用的辅助诊断，并检验知识库扩展后证据检索是否仍可靠。

更具体地说，本文讨论的不是“LLM 能否自动诊断故障”，而是：在数据标签不足、核工应用又要求可审计和可追溯的情况下，如何让语言模型安全地参与诊断辅助。

## 2. 问题背景与研究动机

- 核电中子电流记录规模大、通道多，但现有运行/故障信息异构，难以直接构成统一的监督学习标签体系。
- 传统规则流程不易覆盖复杂工况；直接让 LLM 解释数据又容易产生未经证据支持的结论。
- 技术手册能够提供权威依据，但 RAG 在同领域语料扩展、双语查询和分块变化下的可靠性不能想当然。

因此，研究目标是形成一条可复核的链条：

```text
原始中子电流 CSV
  → 受控工具探针发现观测现象
  → 结构化 alert summary
  → 手册检索与多阶段证据组织
  → 带引用的辅助诊断 memo
```

## 3. 当前系统与论文的三条主线

### 3.1 测量侧：零先验诊断 Agent

对原始 CSV 完成时间排序、数据健康检查、形态发现、异常/工况分段、时滞、极值与空间快照等分析。重点输出 spike、zero dropout、共线性/冗余、同步组和工况变化等**观察事实**。

“零先验”应克制地理解：系统不把故障标签库、固定通道物理映射或手工频带作为推理前提；这不表示完全不使用领域知识，也不表示自动确认故障原因。

### 3.2 运行时约束：可审计的工具调用

Workspace blackboard、仅入口接收 CSV 路径、后续工具从状态文件解析活动数据、注册工具白名单和 JSON 容错，共同降低本地小模型在多步工具调用中路径漂移、虚构工具、格式损坏等风险。

这是工程实现细节，也是论文中“受约束而非黑箱 Agent”的重要论点。

### 3.3 知识侧：报告驱动 RAG 与检索鲁棒性

将测量侧条件报告压缩为结构化检索意图，而非直接依赖自由文本提问；从 IAEA 为核心的核工仪控手册中定位证据，形成带出处的 memo。

随后通过核心—补充语料受控扩展、中文/英文查询、自检索与 chunking 网格实验，检验检索层在真实部署条件下的稳定性。

## 4. 当前最有价值的贡献

1. **贴近实际的弱标签问题设定。** 不把工作限制在标签完整、故障类别预先定义的理想数据集。
2. **具有实际约束的诊断工作流。** Agent 的状态、路径和工具调用受到运行时协议管理，而非依赖模型自由发挥。
3. **从观测到证据的可追溯接口。** 数据侧输出是结构化现象，知识侧输出附带可定位的手册依据。
4. **检索实验得到有部署意义的反直觉发现。** 随着同领域补充语料加入，向量相似度可能上升，但预设核心来源的 Top-$k$ 纯度下降；中文短查询对此尤其敏感。
5. **对评测指标的反思。** strict chunk matching 与 document-level relevance 的差异说明重叠切块下仅用 node-level 命中可能低估实际有用检索。

## 5. 目前已有证据可以支持的结论

- 管线可以将代表性 A1/A2 中子电流序列转为包含异常、掉零、共线性等发现的条件报告，并基于手册输出带引用的 memo。
- 在当前 `nomic-embed-text`、当前语料和查询设置下，语料扩展会显著改变核心来源纯度；相似度不能单独作为证据层可靠性的代理指标。
- 在已测试的 chunk/overlap 网格内，语言与查询信息量对结果的影响通常强于微调 overlap。
- document-level Recall@10 高于严格 node-level Recall@10；重叠分块带来的近重复内容是重要原因。

这些应写成**限定条件下的发现**，而非一般性的模型能力结论。

## 6. 当前不足与审稿风险

### 6.1 端到端验证仍以案例为主

现有案例能证明流程可运行、结果具备可读性，但不能独立证明诊断结论正确。应明确区分：

- 数据直接支持的观察事实；
- 手册支持的可能机制或处置建议；
- 仍需工程师或运行记录核实的推断。

### 6.2 论文可能显得由三项工作拼接而成

Agent、运行时约束与 retrieval study 需要持续由同一个问题串起：**检索层的证据可靠性决定诊断 memo 是否可被信任。** 检索实验不能像附加 benchmark，而应被呈现为系统证据层的压力测试。

### 6.3 core purity 不等于通用相关性

Non-core 文档是同领域补充资料，排在前面未必错误。本文中的 core purity 应定义为：

> 当部署策略要求优先引用一组预先认定的权威来源时，检索系统维持该来源优先级的能力。

它不应被直接称为唯一的 relevance 指标。理想情况下，应补充小规模人工相关性/证据支持标注。

### 6.4 语言结论的外推范围有限

“语言影响大于 chunking”仅在当前嵌入模型、语料、查询集和参数网格下成立。更换多语嵌入模型、查询模板或重排序器后，结论可能改变。

## 7. 推荐的统一叙事

```text
弱标签、高审计要求的中子电流诊断
      ↓
受约束的零先验工具探针：产生可核查现象
      ↓
结构化 alert summary：隔离自由文本与检索接口
      ↓
手册 RAG：生成可回溯的证据与辅助解释
      ↓
检索鲁棒性评测：检验语料、语言与分块对证据层的影响
      ↓
部署建议：术语增强、来源策略、metadata filter / reranker、人工复核
```

建议将系统定位为“evidence-constrained diagnostic workflow（证据约束的诊断工作流）”，而不是“自动故障诊断器”。

## 8. 建议采用的贡献表述

1. 提出面向弱标签中子电流数据的零先验、工具驱动诊断工作流，并以受控 workspace 将原始时序数据转为可审计条件报告。
2. 提出报告驱动的多阶段手册 RAG，将观测到的现象转为结构化检索需求，形成带可追溯出处的辅助诊断 memo。
3. 在核心—补充语料受控扩展、双语查询和自检索实验中，量化检索相似度、来源优先级与证据可靠性之间的脱钩，并据此给出部署边界。

## 9. 写作与主张边界

推荐使用：辅助研判、现象发现、证据定位、可追溯解释、候选机制、需人工核查。

避免使用：自动确认故障、替代工程师、证明根因、系统已具备运行决策能力。

论文应明确保留人类工程师在最终核查与决策环节中的角色。

## 12. 当前修改边界：动什么，不动什么

### 12.1 本阶段应当动：论文的论证与证据呈现

优先修改 `paper/` 中的叙事、表述和结果组织，而不是改变已经跑通的核心系统。

| 范围 | 建议动作 | 目标 |
|---|---|---|
| 标题、摘要、引言、结论 | 围绕“证据约束的弱标签诊断工作流”收紧主线 | 让 Agent、RAG 与 retrieval study 成为一个问题的三个环节 |
| 系统章节 | 明确区分观测事实、证据支持的解释、待人工核查的推断 | 避免把辅助诊断写成自动故障确认 |
| 评测章节 | 精确定义 core purity 的部署含义与适用边界 | 避免将来源优先级误表述为通用相关性 |
| 结果章节 | 将已有 CSV 汇总为正式图表；以精确数值替换“约”“典型”等模糊说法 | 让主张可追溯、可复核 |
| 案例章节 | 强化“数据现象 → 检索证据 → memo”的对应关系 | 证明端到端链条，而非只展示漂亮输出 |
| 局限性 | 主动写明案例验证、单一嵌入模型、无 generation-side factuality benchmark 等边界 | 预先回应审稿质疑 |

### 12.2 本阶段暂不动：核心实现与原始实验资产

以下内容应冻结，除非后续明确决定做新增实验：

- 不重构 `code_ref/` 的 Agent、工具路由和 workspace 协议；当前设计本身是论文贡献的一部分。
- 不改写或清理原始中子电流数据、案例报告、向量索引及已有实验 CSV；它们是证据资产，应保持可追溯。
- 不在当前无 GPU、无 Python 运行环境中尝试重跑 17 组索引或本地模型推理。
- 不为了追求“自动诊断”而补造故障标签、准确率或恢复率；没有外部依据的数值不应进入论文。
- 不把 non-core 资料简单删除以换取更高 core purity；它们是受控扩展实验的必要组成。

### 12.3 可作为下一阶段的新增工作，但现在不预设为必须

- 小规模专家评估：现象准确性、引文适切性、memo 的可操作性。
- 小型人工 query--document relevance / citation-support 标注集。
- metadata filter、来源优先级、reranker 或多语 embedding 的消融/改进实验。
- 端到端生成侧的 faithfulness 或 citation correctness 评测。

这些会显著增强论文，但应在先完成“已有证据的严谨写法”后，再根据目标期刊、可获得的专家时间和计算资源决定是否投入。

## 13. 当前篇幅判断

- `main2.pdf` 为 17 页的 Elsevier 单栏预印本版式；从 PDF 提取的文本约 4,550 词，其中包含标题页、参考文献和附属文字，正文实际约为 3,500 词级别。
- 对本研究范围而言，当前稿件偏短，但问题不是缺少泛泛背景，而是方法复现信息、实验设计、结果量化和案例证据链仍不够密。
- 在未确定期刊硬性要求前，建议将正文目标设为约 6,000--7,500 英文词；最终双栏排版页数会显著少于当前 12pt 单栏预印本页数。

优先增加的内容依次为：实验可复现细节、主要结果表/图及不确定性、案例中的“现象--证据--人工核查”映射、局限性与部署建议。不要为了凑篇幅大幅扩写通用 LLM/RAG 背景。
