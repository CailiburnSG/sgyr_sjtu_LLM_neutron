# 平衡 80 例金标准草稿（仅来自 event_groups）

本目录是当前用于训练/验证设计的 80 例金标准草稿。事件来源**仅限** `goldencard/event_groups/` 的
8 组、共 80 张事件卡；不再从 `eventcard/output/` 追加切分事件。

先固定每项建议 20 例，再构造事件组合：

| 建议 | 事件原子池 | 案例数 |
| --- | --- | ---: |
| A1 查同一时段现场是否有操作或校准 | `positive_spike` 的单通道组 + 多通道组 | 20 |
| A2 横向对比其他传感器通道是否出现类似问题 | `negative_drop` 的单通道组 + 多通道组 | 20 |
| A3 查数据记录和时间戳在处理层面是否有问题 | `short_zero` 的多通道组 + `sustained_zero` 的多通道组 | 20 |
| A4 查信号/数据传输路径是否异常 | `short_zero` 的单通道组 + `sustained_zero` 的单通道组 | 20 |

每项建议内部均为：5 个单事件、5 个双事件、5 个三事件和 5 个四事件案例。单事件在两组事件池间
轮换；多事件案例覆盖两个池。每个事件原子均衡复用 2--3 次，80 个事件组合均不重复。

每例还包含一个三证据组合：该建议下 5 张经人工筛选的直接支持卡中取 3 张。5 选 3 的 10 种组合在
该建议的 20 个案例中各使用两次。具体卡片与用途见 [证据组合定义.md](证据组合定义.md)。

事件 ID 只保留在 `trace.source_event_ids` 用于追溯，不进入模型输入；模型输入是事件类型、通道
数量、作用范围、持续时间和组合模式的摘要。

## 文件

- `allocation.md`：冻结的建议配额与事件池映射；
- `build_balanced_80.py`：可重复构造案例；
- `goldcase_balanced_80.jsonl`：80 个结构化案例；
- `一页总览表.md`：人工审阅表。
