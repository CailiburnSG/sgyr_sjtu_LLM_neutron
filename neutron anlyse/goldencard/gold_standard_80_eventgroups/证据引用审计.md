# 当前 80 例的证据引用审计

审计对象为 `goldcase_balanced_80.jsonl` 的证据组合。它描述当前的金标准草稿，不把受控组合规则误称为
实际部署时的检索规则。

## 当前统计

| 项目 | 数量 |
| --- | ---: |
| 金标准案例 | 80 |
| 每例证据卡 | 3 |
| 证据引用槽位 | 240 |
| 实际使用的不同证据卡 | 20 |
| 每项建议的直接支持卡 | 5 |
| 每项建议的三卡组合 | 10 |
| 每种三卡组合出现次数 | 2 |
| 单张卡出现次数 | 12 |

四类建议之间不共享证据卡。因此单卡的 12 次复用均发生在同一建议类别内，并非把同一条文献证据标成多个
不相干建议。相比此前的“12 卡、每例 1 卡”稿，卡片来源扩展为 20 张，组合标签扩展为 40 种；代价是三卡
输出使每张卡的**绝对引用次数**升高。这是组合标注带来的正常结果，不能仅用单卡次数判断重复问题。

## 各建议如何使用资料

| 建议 | 资料作用 |
| --- | --- |
| A1 查同一时段现场是否有操作或校准 | 尖峰/离群值与通道检查、校准的关系；通道运行/旁路/校准模式；独立通道测试。 |
| A2 横向对比其他传感器通道是否出现类似问题 | 探测器电流的时间/同链比较；物理工况导致的通道差异；冗余通道与群体估计。 |
| A3 查数据记录和时间戳在处理层面是否有问题 | 静态数据合格性；缺失、卡滞、离群；historian 时间戳、压缩、采样和相关性损失。 |
| A4 查信号/数据传输路径是否异常 | 变送器电流与开路语境；电流—电压转换、隔离、调理、滤波、ADC 与同步多通道记录。 |

具体 20 张卡及其在组合中的作用见 [证据组合定义.md](证据组合定义.md)。

## 应如何理解“重复”

本稿真正要避免的是以下两类重复：

1. **单一证据唯一决定标签**：模型只要背一张卡就能猜出建议；
2. **同一证据跨建议混标**：一张卡被无边界地用来支持 A1--A4。

当前结构已避免第二类，并通过三卡组合削弱第一类；但它仍是受控的第一版金标准。三卡必须是指向同一
检查建议的并列直接依据，而非来自不同功能群的推理链。后续人工审阅时，应按事件组的具体形态替换组合中
不够贴合的一张卡，而不是为了增加多样性加入弱相关资料。
