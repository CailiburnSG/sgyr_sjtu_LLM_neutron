# 历史单事件 goldcard 草案结构（v1，不作为当前金标准）

> 当前金标准单位是“事件组合预检案例”，规则见[预检案例金标准与量化设计.md](预检案例金标准与量化设计.md)，
> 实际试标草稿见 `drafts/precheck_case_pilot_10/`。本文件只保留旧单事件草案的历史结构说明。

## 1. 目的

一张 goldencard 不是自然语言报告，也不是故障诊断结论。它是一个可评分的结构化案例，用于
评价系统能否从事件卡中检索到直接支持证据，并选择当前案例适用的固定检查行为。

```text
必要事件要素 + 固定候选证据包
    → 人工证据关联判定
    → 人工确认的检查行为及其证据依据
```

评分的正例是 `(event_id, evidence_id, action_id)` 三元组。只有一个证据被人工判为
`direct_support`，且它直接支撑该行为时，才可构成正三元组。

## 2. JSON 结构

```json
{
  "goldcard_id": "GC-0001",
  "event": {
    "event_id": "...",
    "duration_seconds": 1.0,
    "channel_count": 2,
    "scope": "multi_channel_temporal_cluster"
  },
  "evidence": [
    {
      "evidence_id": "...",
      "content": "证据卡正文",
      "annotation": {
        "label": "null | direct_support | related_but_insufficient | not_relevant",
        "review_status": "pending_user_review | confirmed",
        "rationale": "人工判断该证据与本事件预检任务的关系"
      }
    }
  ],
  "gold_action_links": [
    {
      "action_id": "on_site_operation_or_calibration_check",
      "evidence_ids": ["..."]
    }
  ]
}
```

`event` 只保留本任务需要的四项事件要素；事件完整字段仍只保存在 `event_groups/` 中。
草稿卡的 `annotation.label`、`annotation.rationale` 与 `gold_action_links` 均为空；只有人工标注
后才写入。一项检查行为可由一至多张 `direct_support` 证据共同支撑。

## 3. 标注流程

1. 冻结 `event` 和三条候选证据；此后不得因标注结果替换候选。
2. 在每条证据的 `annotation` 中标记 `direct_support`、`related_but_insufficient` 或 `not_relevant`。
3. 只从[固定检查行为](固定检查行为.md)的四个 `action_id` 中选择动作。
4. 只有 `direct_support` 证据可进入 `gold_action_links.evidence_ids`；一项动作可由多张证据支撑。
5. 三条候选证据均确认后，该 goldcard 才可进入评分集。

## 4. 不允许的标注方式

- 先选动作，再为既定动作寻找无关或仅主题相关的引用；
- 把 `related_but_insufficient` 证据作为动作正例；
- 仅因事件类型相同，就为所有事件赋予相同动作；
- 用自然语言报告中的修辞替代 `action_id`；
- 将检查行为写成“已确认的故障原因”；
- 因候选检索不理想而在人工标注后追加候选证据。

## 5. 评价对应关系

| 任务 | 预测对象 | 金标准字段 | 指标 |
|---|---|---|---|
| 证据检索 | `evidence_id` | `evidence[].annotation.label=direct_support` | Recall@K、Precision@K |
| 行为选择 | `action_id` 集合 | `gold_action_links` 去重后的 `action_id` | micro/macro-F1、Exact Match |
| 证据辅助行为 | `(evidence_id, action_id)` | `gold_action_links` | 三元组 Precision、Recall、F1 |

自然语言报告仅是后续展示层。若生成报告，其引用、行为 ID、条件和边界都必须可回填到本卡，
但报告文本本身不参与本版的主要金标准标注。
