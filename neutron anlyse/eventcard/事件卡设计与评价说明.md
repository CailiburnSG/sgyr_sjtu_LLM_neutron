# 事件卡设计、聚合逻辑与评价说明

本文档固定事件卡模块的研究边界、数据结构和后续实验指标，可作为论文“方法”和“实验设计”两章的写作底稿。正式输入为原始 CSV；历史快照不属于正式方法和正式实验数据。

## 1. 研究对象与边界

研究对象是多通道中子电流长时序中可由规则检测的**数据现象**，例如短时零值、持续零值、尖峰或突降。系统的输出是供人工预检、资料检索和报告生成使用的结构化事件描述。

系统不以事件卡确认故障类型、设备失效机理、因果链或安全状态。多通道事件只表示多个通道在相近时间内出现可观察模式；它不等同于多个通道具有共同物理原因。

## 2. 三层数据结构

```text
原始 CSV
  → 原子事件表 A
  → 单通道事件卡表 C
  → 聚合事件卡表 E
```

### 2.1 原子事件表 A

一行对应一个通道的一段检测结果：

```text
atomic_event_id, record_id, event_type, channel,
time_start, time_end, source
```

`source` 保存检测器名称和冻结后的参数，例如零值阈值、连续采样点数、滚动窗口、MAD 阈值等。原子事件是后续所有卡片的最小可追溯单位。

### 2.2 单通道事件卡表 C

对于相同 `record_id`、`channel` 和 `event_type` 的原子事件，按时间顺序合并相邻片段。每张卡包括：

```text
channel_card_id, record_id, event_type, channel,
time_start, time_end, source_atomic_event_ids, provenance
```

这一步处理的是“同一个通道内是否属于同一段现象”，不使用其他通道的信息。

### 2.3 聚合事件卡表 E

对于相同 `record_id` 和 `event_type` 的单通道卡，按时间区间聚合，形成系统后续阅读的唯一事件入口：

```text
event_id, record_id, event_type, time_start, time_end,
channels, channel_count, scope, source_channel_card_ids, provenance
```

`scope` 有两种取值：

- `multi_channel_temporal_cluster`：聚合簇中涉及两个及以上通道；该名称只表示时间邻近聚合，不表示严格同步；
- `single_channel`：没有其他通道卡可合并的孤立事件。

因此孤立事件不会丢失。每个原子事件都必须沿着 `A → C → E` 被引用到至少一张聚合事件卡中。

## 3. 持续时间不一致时如何聚合

卡片不需要被切成相同长度。每张单通道卡表示一个闭区间：

\[
I_i=[t_i^{start},t_i^{end}].
\]

设聚合容忍窗口为 \(\Delta_a\)。若下一张卡的开始时间不晚于当前聚合簇最晚结束时间加 \(\Delta_a\)，即：

\[
t_j^{start} \leq \max_{i\in G}(t_i^{end}) + \Delta_a,
\]

则将其加入同一聚合簇 \(G\)。最终卡片的时间范围是：

\[
[\min_{i\in G}t_i^{start},\ \max_{i\in G}t_i^{end}].
\]

这是**链式区间聚合**：只要时间上重叠或间隔不超过 \(\Delta_a\)，就可形成同一整体观测事件。它适合描述“不同通道先后出现相近模式”的连续过程，但不应被表述为严格同步。各通道原始区间通过 `source_channel_card_ids` 保留，不会被聚合时间范围覆盖或抹去。

同理，单通道层使用独立窗口 \(\Delta_c\)，只合并同一通道、同一类型的相邻原子事件。\(\Delta_c\) 与 \(\Delta_a\) 应在正式实验前冻结，并在论文中报告。

## 4. 可直接用于论文的方法表述

> 本文首先对每个通道的原始时序独立执行确定性事件检测，将检测结果表示为带有时间区间、通道标识和检测参数的原子事件。随后，在同一通道内按照事件类型与时间邻近性合并相邻原子事件，得到单通道事件卡。最后，对同一记录中同类型的单通道事件卡执行基于时间区间的聚合，形成跨通道事件卡。聚合卡保留其来源单通道卡标识，单通道卡进一步保留来源原子事件标识，从而实现从报告对象到原始观测和检测规则的逐级追溯。对未与其他通道合并的事件，系统以单通道聚合卡保留，而非丢弃。

## 5. 量化评价

指标分为三组。第一组可不依赖人工标签，用于验证系统完整性和人工阅读负担；第二、三组需建立小规模人工标注集，才可用于说明方法质量。

### 5.1 无需人工标签：结构完整性与压缩效果

这些指标不能证明检测“正确”，但能证明产物没有断链且确实减少了阅读对象。

| 指标 | 定义 | 预期 |
|---|---|---|
| 原子覆盖率 | 被至少一张单通道卡引用的原子事件数 / 原子事件总数 | 100% |
| 单通道卡覆盖率 | 被至少一张聚合卡引用的单通道卡数 / 单通道卡总数 | 100% |
| 引用完整率 | 所有 `source_*_ids` 均能在上游表找到的比例 | 100% |
| 原子到聚合压缩比 | \(|A|/|E|\) | 描述阅读负担缩减，不单独比较优劣 |
| 多通道卡比例 | `multi_channel_temporal_cluster` 卡数 / \(|E|\) | 描述数据中可聚合现象比例 |
| 平均通道覆盖数 | \(\frac{1}{|E|}\sum_{e\in E}|channels(e)|\) | 描述聚合规模 |

### 5.2 需要人工标签：事件检测质量

从不同记录、不同事件类型、不同持续时间中分层抽取一小批时间窗，由你或领域人员标出：事件类型、受影响通道和起止时间。标注的是“可观察数据现象”，不是故障机理。

将预测卡与人工事件按照“类型一致，且时间区间 IoU 不低于阈值 \(\tau\)”匹配：

\[
IoU(I_p,I_r)=\frac{|I_p\cap I_r|}{|I_p\cup I_r|}.
\]

可报告：

| 指标 | 含义 |
|---|---|
| Event Precision / Recall / F1 | 预测事件是否命中人工事件 |
| 类型准确率 | 已匹配事件的 `event_type` 是否一致 |
| 起点/终点 MAE | \(|t_p^{start}-t_r^{start}|\)、\(|t_p^{end}-t_r^{end}|\) 的平均误差 |
| 持续时间相对误差 | 预测持续时间与标注持续时间的偏差 |
| 通道集合 Jaccard | \(\frac{|C_p\cap C_r|}{|C_p\cup C_r|}\)，评价涉及通道是否正确 |

建议先标注 80–150 个候选事件，覆盖零值、尖峰、单通道和多通道情形。标注规模有限时，应报告置信区间或至少说明样本构成，而不要夸大泛化性。

### 5.3 需要人工标签：聚合质量

这组指标专门回答“长度不一、起止不齐的单通道卡，是否被合理组织为整体事件”。标注者无需重标原始信号，只需查看单通道卡及其原始时间窗，判断哪些卡属于同一个整体观测事件。

| 指标 | 含义 |
|---|---|
| 成对聚合 Precision / Recall / F1 | 任意两张单通道卡是否应在同一聚合事件中；评价过度合并与漏合并 |
| 聚合纯度 | 一张预测聚合卡中的单通道卡有多少确属同一人工事件；低值表示误合并 |
| 聚合完整度 | 一个人工事件中的单通道卡有多少被放进同一预测卡；低值表示碎片化 |
| 碎片率 | 一个人工整体事件被拆分为两张及以上预测卡的比例 |
| 误合并率 | 一张预测卡混入两个及以上人工整体事件的比例 |

最有价值的消融实验是只改变 \(\Delta_a\)，例如 0、1、3、5 秒，比较上述聚合指标和最终卡片数量。这样可以直接说明选择该聚合窗口的依据，而不是任意设定阈值。

## 6. 与后续检索和 LLM 的关系

事件卡模块的核心指标是事件检测和事件组织质量，不是 embedding 相似度。后续检索模块可使用聚合事件卡的 `event_type`、通道范围、持续时间和观测事实生成受控查询；LLM 则只能基于事件卡和可追溯资料生成预检说明。

如果后续引入 LLM，还应单独评价报告的事实一致性、证据引用覆盖率和人工可用性；这些指标不应混入本模块的事件卡评价。
