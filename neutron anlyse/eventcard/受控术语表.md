# 事件卡受控术语表（v1）

本表是 `eventcard/`、`evidencecard/` 和后续检索/报告共用的唯一命名来源。JSON 字段值使用英文 ASCII 代码；中文仅用于论文和人工阅读。

最重要的边界：**信号平稳不等于机组正常运行。** 因此“事件模式”和“运行工况”是两个不同字段，不能互相替代。

## 1. Observable event type

| Code | Chinese label | Definition | Current source |
|---|---|---|---|
| `short_zero` | 短零值段 | A contiguous near-zero run no longer than the frozen short-zero threshold. | CSV detector |
| `sustained_zero` | 持续零值段 | A contiguous near-zero run longer than the frozen short-zero threshold. | CSV detector |
| `positive_spike` | 正向尖峰 | A positive local deviation from the rolling-median baseline exceeding frozen thresholds. In the current detector it is a candidate label; return-to-baseline has not yet been separately verified. | CSV detector |
| `negative_drop` | 负向突降 | A negative local deviation from the rolling-median baseline exceeding frozen thresholds. In the current detector it is a candidate label; return-to-baseline has not yet been separately verified. | CSV detector |
| `upward_trend` | 持续上升 | A sustained positive change across a frozen minimum duration/window. It is not a short spike. | Reserved: trend detector not yet enabled |
| `downward_trend` | 持续下降 | A sustained negative change across a frozen minimum duration/window. It is not a short negative drop. | Reserved: trend detector not yet enabled |
| `transient_deviation` | 暂态偏离 | A time-bounded departure from a reference level whose direction cannot be robustly assigned, or is supplied by an external/legacy detector. | Reserved: external or future detector |

The relation is deliberately explicit: `positive_spike` and `negative_drop` are directional **short transients**; `upward_trend` and `downward_trend` are directional **sustained changes**. `transient_deviation` is a neutral fallback, not a synonym for every event. These are observations only. None means detector failure, reactor transient, calibration activity, or a confirmed physical cause.

### Selection rule

1. Use `positive_spike` / `negative_drop` when the change is short and returns near the local baseline. The current v1 detector supplies candidates only, so this distinction must be verified before calling the output a confirmed short transient in a result table.
2. Use `upward_trend` / `downward_trend` when the direction persists through the frozen trend window; do not call it a spike/drop merely because the start is steep.
3. Use `transient_deviation` only when a finite deviation is clear but its sign is not reliably determined. Do not use it if a directional term is available.
4. Do not use an event type to state a physical operating condition. Operating labels belong in `operating_context`.

## 2. Operating context

`operating_context` is optional metadata for an event card or, more commonly, for a reference window. It must carry a `context_source` and must not be inferred from event type alone.

| Code | Chinese label | Assignment rule | Permitted statement |
|---|---|---|---|
| `normal_operation_confirmed` | 已确认正常运行 | Assigned only from an operations log, approved status flag, or other external plant record. | The external record labels this interval as normal operation. |
| `steady_signal_baseline` | 平稳信号基线 | Deterministic data rule: selected channels remain within frozen stability limits and no v1 event is detected in the reference window. | This is a stable-signal reference window, not proof of normal plant operation. |
| `operating_transition_confirmed` | 已确认运行过渡 | Assigned only from an external record identifying startup, shutdown, power change, or another operational transition. | The external record labels this interval as an operating transition. |
| `maintenance_or_test_confirmed` | 已确认维护或试验 | Assigned only from a maintenance, calibration, channel-check, or test record. | The external record identifies maintenance or test context. |
| `operation_context_unknown` | 工况未知 | Used when no reliable external context exists. | Operating context was not available for this record. |

For the current local CSV, no external operations-status record has yet been connected. Its cards therefore must remain `operation_context_unknown`; we must not label them `normal_operation_confirmed` merely because the signal looks calm.

## 3. Aggregation scope

| Code | Chinese label | Definition |
|---|---|---|
| `single_channel` | 单通道 | The aggregated card contains one affected channel. |
| `multi_channel_temporal_cluster` | 多通道时间聚合簇 | Two or more same-type channel cards are linked by the frozen time-aggregation window. It does not imply strict synchrony or a common cause. |

## 4. Evidence-card applicability

`applicability` is an ASCII-only list, not a prose conclusion. The current permitted values are:

| Code | Intended retrieval use |
|---|---|
| `data_qualification` | General data-quality pre-screening |
| `missing_data_check` | Missing-data or acquisition-gap check |
| `spike_data_qualification` | Transient/spike qualification check |
| `stuck_signal_screening` | Long fixed-value or zero-segment screen |
| `historian_sampling_check` | Sampling, timestamp, compression, or historian context |
| `channel_comparison` | Generic peer/redundant-channel comparison context |
| `neutron_current_channel_comparison` | Neutron-current measurement-channel comparison context |
| `neutron_current_temporal_comparison` | Neutron-current temporal comparison context |
| `signal_path_context` | Generic instrument-loop or signal-path context |
| `neutron_current_signal_path_context` | Neutron-current signal-path context |
| `calibration_activity_check` | Calibration or channel-check context |
| `baseline_reference_selection` | Selection or qualification of a normal/stable reference baseline |
| `neutron_current_measurement_context` | Neutron-current measurement principle or detector-mode context |
| `detector_response_time_context` | Detector response-time or dynamic-response context |
| `gamma_contribution_check` | Gamma contribution or mixed-field interference context |
| `detector_calibration_context` | Detector calibration or response-proportionality context |
| `signal_quality_context` | Detector or acquisition signal-quality context |

## 5. Minimal JSON convention

```json
{
  "event_type": "positive_spike",
  "scope": "multi_channel_temporal_cluster",
  "operating_context": "operation_context_unknown",
  "context_source": null
}
```

When a confirmed normal window is later imported, use `normal_operation_confirmed` and record the external source identifier in `context_source`. A derived stable baseline uses `steady_signal_baseline` and records its frozen rule/version instead.
