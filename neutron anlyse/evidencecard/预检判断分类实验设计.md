# 事件—证据辅助预检：判断分类实验设计

## 1. 与参考论文的对应关系

参考论文 ChatCAD 的主实验将影像与 CAD 输出交给 LLM 形成报告，再将报告归约为固定的疾病
观察标签，并与标准标签计算 Precision、Recall 和 F1。本研究可采用同样的量化逻辑，但把
评价对象限定为**预检判断**，而不是未经外部真值支持的具体故障原因：

```text
ChatCAD：影像 + CAD 输出 → LLM 报告 → 疾病观察标签 → 与标准标签计算 F1

本研究：原始记录 → 事件卡 + 证据卡 → LLM 预检报告 → 预检处置标签 → 与标准标签计算 F1
```

因此，论文中的主术语建议为“预检处置建议分类性能”（pre-screening action recommendation
performance）或“异常预检准确率”，不称为“故障原因诊断准确率”。后者只有在取得维护
工单、校准记录、运行日志或专家追溯结论后才可成立。

## 2. 金标准案例

一个金标准案例以一个独立时间窗口/聚合事件卡为中心，并包含：

```text
事件卡：观测到的事件类型、时间、通道和范围
标准预检处置标签：该案例应输出的核查方向
标准直接支持证据卡：可支撑每项核查方向的证据 ID
允许的建议表述与适用性边界
不能确认的结论
```

### 2.1 v1 预检处置标签

建议先冻结以下五个多标签类别：

| 标签 | 含义 |
|---|---|
| `data_qualification` | 先进行异常值、尖峰、缺失或卡滞等数据质量筛查 |
| `calibration_activity_check` | 核查校准、通道检查或测试活动记录 |
| `historian_sampling_check` | 核查采集、时间戳、采样或历史库链路 |
| `channel_comparison` | 与同类/相邻通道或可确认的参考基线进行比较 |
| `signal_path_context` | 核查测量和信号传输链路的配置或背景 |

另设置一个安全边界标签：

| 标签 | 含义 |
|---|---|
| `insufficient_evidence_for_specific_action` | 当前资料不足以支撑更具体的核查建议，必须保留人工复核 |

一个案例可同时有多个正标签。例如多通道正尖峰可标为
`data_qualification`、`calibration_activity_check` 和 `channel_comparison`，并不意味着
已经确认发生校准、共因失效或任何具体故障。

### 2.2 样本构成和切分

100 例可作为先导评价集，推荐构成为：

```text
20 × short_zero
20 × sustained_zero
20 × positive_spike
20 × negative_drop
20 × no_anomaly（或明确的无异常对照窗口）
```

每类尽量平衡单通道和多通道范围。先导集可分为开发集 20 例和冻结测试集 80 例：开发集只
用于冻结标签定义、受控查询、top-K 和提示词；测试集不参与任何调参。若要得到与参考论文
接近的说服力，后续应扩展为约 300 例，并在类别之间平衡。

切分单位必须是原始记录或互不重叠的时间段，不能把同一长记录中的相邻、模式高度相似事件
随机拆分到开发与测试两侧。

## 3. 对照实验

所有系统使用相同的事件集合、输出标签词表、模型参数和评测程序。

| 系统 | 输入 | 目的 |
|---|---|---|
| B0 | 事件卡 → 确定性模板 | 不使用 LLM 的事实与边界基线 |
| B1 | 事件卡 → LLM | 量化自由生成的遗漏与越界风险 |
| B2 | 事件卡 + 自动检索证据 → LLM | 实际可部署的完整系统 |
| B3 | 事件卡 + 金标准直接支持证据 → LLM | 排除检索误差后的证据使用上限 |
| B4 | 自然语言事件摘要 + B3 证据 → LLM | 检验结构化事件卡的贡献 |

B2 是主系统。B3 用于定位瓶颈：若 B3 明显优于 B1，则证据约束有效；若 B2 接近 B3，则
检索已经足够有效；若 B3 高而 B2 低，则改进重点应是检索而非 LLM。

## 4. 主量化结果：预检判断分类

从每个系统输出的结构化报告中读取预检处置标签，与金标准多标签集合比较，报告：

- 每个标签的 Precision、Recall、F1；
- macro-F1（各类同等权重）；
- micro-F1（整体标签判断能力）；
- Exact Match Ratio，即一个案例的完整建议集合是否完全正确；
- 每个标签的 TP、FP、FN，以及必要时的混淆矩阵。

## 5. 检索和证据链评价

除最终建议 F1 外，B2 还应单独评价是否找到正确资料：

- Evidence Recall@K：top-K 中至少出现一张金标准 `direct_support` 卡的事件比例；
- Evidence Precision@K：top-K 中 `direct_support` 卡的比例；
- 证据可用率：每个事件是否至少有一张可支持建议的证据；
- 引用可定位率：报告引用能否回到合法的证据卡、来源、章节和行号；
- 引用支撑率：报告说法—引用对中，被人工判为直接支持的比例。

这将最终建议分解为可解释链条：未检出正确证据、已检出但未正确使用，或生成报告时越界。

## 6. 忠实性与安全边界

系统还应报告：

- 字段忠实率和关键字段遗漏率：事件类型、时间、通道/数量、范围及限制是否被正确复述；
- 无证据断言率：没有合同内证据却给出具体说明或建议的比例；
- 过度诊断率：将观测现象、时间共现或资料背景写成具体故障/机理确认的报告比例；
- 克制率：无直接证据时明确保留不确定性、且未追加具体推断的比例。

自动合同校验可识别未知引用、无引用建议和显性诊断/因果语句；语义层面的引用支撑和过度
诊断应由盲审人工复核。建议随机抽取至少 20% 的案例由第二审阅者复标并报告 Cohen's kappa。

## 7. 可复现执行顺序

1. 冻结预检标签词表、事件卡版本、证据卡版本、资料目录和数据切分；
2. 固定候选证据包，人工完成事件—证据和预检处置标签复核；
3. 仅使用开发集冻结检索参数、提示词、模型、温度和输出格式；
4. 对冻结测试集运行 B0--B4，保存每次结构化原始输出、模型版本和随机种子；
5. 先运行自动合同与字段校验，再进行盲审；
6. 按事件汇总指标，报告 1,000 次事件级 bootstrap 的 95% 置信区间；
7. 分别报告事件提取、检索、预检判断分类、报告忠实性和结论边界，不外推为真实故障原因
   的诊断准确率。
