# 事件—证据检索与受约束预检报告：实验设计 v1

## 目标、数据与冻结

评价单位为“事件卡—固定候选证据包—报告”，目标是发现可观察现象、给出可复查资料与
人工核查线索；它不评价真实故障或机理。100 个正式案例按 `event_type × scope ×
duration_bin × record_id` 分层，每例冻结 5--10 张候选卡，并由人工逐条标为
`direct_support`、`related_but_insufficient` 或 `not_relevant`。只有全部标注为
`confirmed` 的案例才是金标准。

当前 `A1_1_head5000` 只含正尖峰和负突降，故生成的 100 条仅为流程演练候选包，不能称为
完整金标准。缺失的短/持续零值、趋势和一般瞬态分层必须等正式记录接入后补齐。候选冻结后
不得根据标注结果替换候选；建议开发 20 例用于冻结词表、K 和提示词，保留 80 例作最终测试。

## 对照、检索与复现

| 系统 | 用途 |
|---|---|
| S0 | 事件卡 → 确定性模板，事实基线 |
| S1 | 事件卡 → 无资料约束 LLM，观察自由生成越界 |
| S2 | 事件卡 → 受控检索候选包，只评价检索 |
| S3 | 事件卡 + 已确认直接证据 → 受约束 LLM，完整系统 |
| S4 | 自然语言事件摘要 + S3 证据，验证结构化事件卡价值 |

S1/S3/S4 固定模型、温度、最大输出与事件集合；记录模型、提示词、种子、事件/证据版本和
检索器版本。v1 检索在 `core` 与 `domain` 中使用 `event_type × scope` 的程序化词表和
BM25 top-8 基线；可添加向量/重排消融，但不是主要贡献，且必须使用相同过滤范围。

\[
Recall@K=\frac{\#\{事件：top-K中至少一张direct\_support\}}{\#事件},\qquad
Precision@K=\frac{\#direct\_support\ cards\ in\ top-K}{K}.
\]

同时报告证据可用率、每种事件的宏平均和 1,000 次事件级 bootstrap 95% 区间。
`related_but_insufficient` 不能算作正例，可另报主题相关率。

## 报告合同与指标

S3 的输入只能来自 `confirmed + direct_support` 链接。每条证据说明或核查建议都必须引用合同
中的证据 ID；没有直接证据时必须说明资料不足，不能补全判断。自动验证拒绝未知引用、无
引用建议、故障诊断和因果断言；之后由盲审复核语义。

| 指标 | 成功定义 |
|---|---|
| 字段忠实率 / 关键字段遗漏率 | 正确复述事件类型、时间、通道/数量、范围与限制 |
| 引用可定位率 | 引用卡在合同内且有文档、章节和行号 |
| 引用支撑率 | 人工判为 `direct_support` 的报告说法—引用对比例 |
| 无证据断言率 | 无合同证据却给出具体说明或建议的比例 |
| 过度诊断率 | 将现象、相关性或资料背景写成故障/机理确认的报告比例 |
| 克制率 | 无直接证据时保留不确定性而无具体推断的比例 |

建议随机抽取 20% 由第二审阅者复标并报告 Cohen's kappa。运行顺序为：冻结输入与抽样计划、
冻结候选包并人工复核、在开发集定参、运行对照并保存原始 JSON、合同检查与盲审、按事件
汇总。论文分开报告事件提取、检索、报告忠实性和结论边界，绝不改写为“故障诊断准确率”。
