# 中子电流预检系统：评价与实验设计

> 系统定位：面向长时、多通道中子电流记录的预检工作流。系统提取可观察现象、连接可定位技术资料，并生成供人工继续核查的报告；不替代真实故障诊断、运行记录或专家判断。

## 1. 评价目标

论文不再将检索排序作为唯一主结果，而分别验证预检系统是否：

1. 提取出定义明确的记录现象；
2. 忠实地将工具结果写入报告；
3. 为说明提供可定位、可核查的资料来源；
4. 在证据不足时保持结论边界，不作过度诊断。

| 层次 | 要回答的问题 | 指标 |
|---|---|---|
| 事件提取 | 数据里的可观察现象有没有被提出来 | 事件 Precision / Recall / F1、时间定位 IoU、通道定位 F1、误报率 |
| 报告忠实性 | LLM 有没有把工具结果写错或漏掉 | 字段忠实率、关键字段遗漏率、数值篡改率 |
| 证据可追溯性 | 报告的说明有没有明确来源 | 引用可定位率、引用支撑率、证据覆盖率 |
| 结论边界 | 系统有没有无证据地下结论 | 无证据断言率、过度诊断率、正确保留/待核查率 |

核心不是一个单一总分，而是证明完整系统能够同时做到：发现现象、如实报告、给出来源、不过度推断。

## 2. 事件提取评价

没有真实故障标签时，仍可评价预检现象的提取正确性。

在留出的原始记录窗口中注入已知现象：

- 单通道孤立零值；
- 多通道同步零值；
- 单通道尖峰；
- 持续偏置或短时掉线。

每个注入样本保存真值：通道、起止时刻、持续长度、幅度、是否多通道同步。检测函数生成事件卡后，与真值对比：

- 事件检测 Precision、Recall、F1；
- 时间区间 IoU；
- 通道定位 macro-F1；
- 正常窗口的误报率；
- 不同强度、持续时间和噪声下的鲁棒性曲线。

这部分只能说明系统对“定义明确的测量记录现象”具有检测和定位能力，不能外推为真实设备故障诊断。

## 3. LLM 报告忠实性评价

所有系统版本接收统一的事件卡和资料证据输入，并使用固定报告结构：

```text
观察到的事实
数据依据
相关技术资料
建议核查事项
不能确认的结论
引用来源
```

报告应被程序重新解析为结构化字段，并与输入事件卡比对。

\[
\text{字段忠实率}
=
\frac{\text{正确复述的必填字段数}}
{\text{事件卡必填字段总数}}
\]

重点检查：

- 通道名称是否正确；
- 时间、持续长度和数值是否正确；
- 单通道/多通道关系是否正确；
- 是否捏造数值或遗漏关键观察；
- 是否将时间关联误表述为因果；
- 是否将观察现象误表述为已确认故障。

可报告的自动指标包括字段忠实率、关键字段遗漏率、数值篡改率和格式合规率。

## 4. 技术资料证据评价

不以“目标文档是否排在第几名”为主问题，而评价报告中的说法是否由资料支撑：

- 引用是否能定位到具体文件、章节或段落；
- 被引用段落是否直接支持对应说法；
- 关键说明是否至少有一条资料来源；
- 没有资料时，模型是否明确写出“无法确认”。

抽样 50–100 个“事件卡—报告说法—引用段落”三元组，按以下规则判定：

```text
直接支持 / 部分相关但不足以支持 / 不支持
```

该判断针对文本证据关系，而不是裁定真实物理机理。可由助手完成初标、保留判断理由与原文定位，再由用户抽查“直接支持”项的一部分。

## 5. 系统级对照与消融

不需要比较大量 embedding 或 LLM。主要比较系统结构：

| 系统 | 用途 |
|---|---|
| S0：规则工具 → 事件卡 | 不生成报告的事实基线 |
| S1：事件卡 → 固定模板报告 | 无 LLM 基线 |
| S2：事件卡 + LLM，无资料/无严格约束 | 检验自由生成的越界风险 |
| S3：事件卡 + 资料检索 + 受约束 LLM | 完整系统 |
| S4：完整系统去掉事件卡结构，只给自然语言摘要 | 检验结构化事件卡的价值 |

各比较回答的问题：

- S0 与 S1：模板能覆盖多少基本预检信息；
- S1 与 S2：LLM 是否引入遗漏、篡改或越界；
- S2 与 S3：资料与引用约束是否减少无证据说法；
- S3 与 S4：事件卡是否提高报告忠实性与完整性。

不同 LLM 模型可作为补充实验，例如在完整系统下比较 Qwen 7B 与 Qwen 14B 对忠实性和越界率的影响；模型品牌/规模不应成为主实验。

## 6. 建议的论文叙事

1. **问题**：长时、多通道中子电流记录的预检依赖人工浏览；数值发现与技术资料之间缺少可追溯连接。
2. **目标**：不是自动诊断，而是生成供人工复核的预检报告。
3. **方法**：规则/工具提取观测事件 → 事件卡 → embedding 召回资料 → 受约束 LLM 生成报告。
4. **评价**：事件正确性、报告忠实性、证据支撑和结论边界。
5. **结果**：完整系统相较模板、无资料 LLM 和无结构摘要，更少遗漏、更少无证据断言、更多可定位来源。
6. **边界**：不替代运行记录、维护信息或专家诊断；仅提供初步筛查与人工核查线索。

## 7. 用户需要确认的事项

用户不需要手工运行全部实验或阅读完整资料库，主要需要：

- 确认首批预检事件类别；
- 确认每类事件卡的必填字段；
- 明确哪些结论属于绝对不能越界的表述；
- 抽查部分“直接支持”的资料标注；
- 如有条件，邀请一位同学或导师对少量报告做盲评。

其余工作，包括事件卡生成、注入测试、检索管线、报告格式、自动指标、对照实验和图表，可由实现流程完成。
