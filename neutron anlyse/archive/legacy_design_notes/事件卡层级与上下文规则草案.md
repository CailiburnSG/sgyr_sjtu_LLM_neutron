# 事件卡层级与上下文规则草案

> 目的：将原始多通道中子电流记录中的可观察现象，整理成可追溯的事件卡。本文档只定义数据观测、时间关系与核查边界；不定义设备故障、物理机理或因果关系。

## 1. 总体层级

```text
原始 CSV
  → 通道级原子观测（一个通道、一次明确现象）
  → 通道内事件序列/episode（必要时合并相邻同类现象）
  → 跨通道聚合事件（同一时间附近、多个通道的同类观测）
  → 事件上下文（前后干净窗口、其他事件、横截面、工况）
  → 预检事件卡
```

事件卡是预检输入，不是故障诊断结论。

## 2. 通道级原子观测

原子观测的最小单位是：**一个通道在一个时刻或连续区间内出现的一种可计算现象**。

### 2.1 零值类

| 类型 | 判定对象 | 最小输出 |
|---|---|---|
| 单点零值 | 单个采样点为零 | 时间、通道、局部基线 |
| 短零值段 | 连续零值长度不超过阈值 \(L_0\) | 起止时间、样本数、前后基线 |
| 持续零值段 | 连续零值长度超过 \(L_0\) | 起止时间、持续长度、是否恢复 |
| 间歇性零值序列 | 同一通道多次短零值、间隔较短 | 各零值段及间隔 |

原则：零值只称为“零值观测/零值段”，不得直接称为设备停机、通道失效或物理异常。

### 2.2 瞬态偏离类

| 类型 | 判定对象 | 最小输出 |
|---|---|---|
| 正向尖峰 | 相对局部中值的正向大偏离 | 起止、峰值时间、峰值、MAD 分数 |
| 负向突降 | 相对局部中值的负向大偏离 | 起止、最低点时间、最低值、MAD 分数 |
| 短瞬态段 | 连续异常采样点组成的短段 | 起止、长度、最大绝对偏差 |
| 重复瞬态序列 | 同一通道重复的尖峰/突降 | 单次事件与间隔 |

尖峰峰值应按最大绝对偏差而非最大原始数值确定，确保负向突降也能被正确定位。

### 2.3 工况/趋势类

| 类型 | 判定对象 | 最小输出 |
|---|---|---|
| 稳定段 | 局部变化低于趋势阈值 | 起止、中值、范围、波动 |
| 上升段 | 平滑后斜率为正且超过阈值 | 起止、斜率、首末值 |
| 下降段 | 平滑后斜率为负且超过阈值 | 起止、斜率、首末值 |
| 持续零值段 | 零值持续的趋势状态 | 起止、长度 |

工况段用于解释事件发生背景；它们本身不必都作为需要检索资料的预检事件卡。

## 3. 通道内事件序列（episode）

同一通道的多个原子观测并不总是独立。应先检查是否构成一个事件序列。

| 情形 | 处理 |
|---|---|
| 同类观测之间间隔很短 | 合并为一个 episode，保留内部子事件 |
| 同类观测之间有足够长的干净稳定段 | 保持为独立事件 |
| 短零值—短恢复—短零值 | 标为间歇性零值 episode，而非误称为多次完全独立事件 |
| 尖峰与零值交替出现 | 保持不同类型，但建立时间相邻关系 |

需要预先定义同通道 episode 合并间隔 \(g_{\text{episode}}\)。该参数应写入配置并在开发集检查敏感性。

## 4. 跨通道聚合事件

跨通道聚合只表达时间与模式上的共同出现，不表达共同机理。

### 4.1 同类事件的时间聚合

满足以下条件的原子观测或 episode 可进入同一聚合候选：

```text
同一记录
且同一事件类型
且时间间隔或时间区间重叠满足聚合窗口 δ
```

建议采用“簇总时间跨度不超过 \(\delta\)”的规则，而不是无限链式相邻合并，防止事件被持续串接扩大。

### 4.2 聚合模式

| 模式 | 条件 | 事件卡表述 |
|---|---|---|
| 单通道局部事件 | 仅一个通道参与 | 单通道零值/瞬态观测 |
| 双/少量通道近同步事件 | 多个通道在 \(\delta\) 内参与 | 多通道近同步观测 |
| 部分通道事件 | 参与比例小于全部通道 | 部分通道共同观测 |
| 广泛通道事件 | 参与比例达到预设阈值 | 多通道广泛共同观测 |
| 时间分散重复事件 | 同类事件发生于不同时间 | 不合并；作为重复模式统计 |

每张聚合卡至少保存：通道集合、总通道数、参与比例、时间离散度、内部原子观测列表及来源。

### 4.3 不应聚合的情形

- 不同记录中的事件；
- 不同类型事件（例如零值与尖峰）；
- 时间间隔超过 \(\delta\) 的事件；
- 仅因通道相关性高而时间不接近的事件。

## 5. 事件上下文

事件上下文不是新事件类型，而是回答“该事件发生前后，记录处于什么状态”。

### 5.1 事件本体与前后窗口

对事件区间 \([t_s,t_e]\)，上下文定义为：

```text
事件本体：[t_s, t_e]
前置窗口：[t_s - W_pre, t_s)
后置窗口：(t_e, t_e + W_post]
```

窗口应随事件持续时间 \(D\) 自适应：

\[
W = \min(W_{\max}, \max(W_{\min}, \gamma D))
\]

例如可在开发阶段采用 \(W_{\min}=60\) 秒、\(\gamma=2\)、\(W_{\max}=600\) 秒，并做敏感性检查。这里不是最终固定数值。

### 5.2 上下文可提取的信息

| 信息 | 含义 |
|---|---|
| 前置基线 | 事件前无其他干扰时的中值、范围、趋势 |
| 后置恢复 | 事件后是否回到前置或局部基线附近 |
| 同期其他通道 | 其他通道是否出现同类观测、幅度变化或稳定状态 |
| 工况背景 | 事件发生于稳定、上升、下降还是持续零值段 |
| 横截面 | 峰值/零值时刻所有通道的读数 |
| 时间关联 | 可选的相关性或领先-滞后统计；不能称为因果 |

### 5.3 前后窗口存在其他事件

若前置或后置窗口包含其他事件，不能把该窗口当作干净稳定基线。

| 情形 | 处理 |
|---|---|
| 同通道、同类型、短间隔事件 | 考虑合并为同一 episode |
| 不同类型或不同通道事件 | 保持独立卡，并记录相邻关系 |
| 其他事件污染前置窗口 | `baseline_status = contaminated`；不得声称事件前稳定 |
| 其他事件污染后置窗口 | `recovery_status = contaminated`；不得声称已恢复 |
| 记录边界不足 | `baseline_status/recovery_status = unavailable` |
| 排除其他事件后仍有足够连续干净片段 | 从最近的干净片段计算基线 |

卡片可记录关系：

```text
preceded_by      前方紧邻事件
followed_by      后方紧邻事件
overlaps_with    时间区间重叠事件
same_episode_as  同类且短间隔的同一序列事件
```

## 6. 预检事件卡的最小字段

```json
{
  "event_id": "...",
  "record_id": "...",
  "event_type": "isolated_zero | sustained_zero | spike | drop | ...",
  "time_start": "...",
  "time_end": "...",
  "channels": ["..."],
  "scope": "single_channel | multi_channel_near_synchronous | ...",
  "data_evidence": {},
  "episode_relations": {},
  "context": {
    "baseline_status": "clean | contaminated | unavailable",
    "recovery_status": "clean | contaminated | unavailable",
    "regime_context": "...",
    "other_channel_context": "..."
  },
  "provenance": {},
  "prohibited_conclusions": []
}
```

## 7. 第一版实施边界

第一版不应覆盖所有情形。建议先实现：

1. 单点/短零值段；
2. 持续零值段；
3. 正向尖峰与负向突降；
4. 同类型事件的跨通道近同步聚合；
5. 前后干净/污染/缺失的上下文状态；
6. 三项上下文：事件前后是否恢复、其他通道是否同步、事件处于稳定段还是趋势段。

后续再增加重复 episode、横截面、相关性和时滞关联。
